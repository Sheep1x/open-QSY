# 官方「Rokid Glasses 裸机开发」要点与踩坑清单

来源：Rokid 开发者文档 → 裸机开发专栏（`custom.rokid.com`，站点 `ff28c865…`，共 10 篇：
简介 / 快速开始 / Sample 工程与页面说明 / 眼镜 UI 设计规范 / 按键与佩戴和折叠 /
原始音频 / 拍照 / 录像 / IMU 与传感器 / 相机预览描边），配合官方示例
`GlassesBareDevSample.zip`（已作为本工程底座）。

> 一句话定性：裸机 = 在眼镜本机跑**普通 Android 应用**，用标准 Android API（CameraX、
> SensorManager、AudioRecord），**不依赖手机端 CXR SDK**。

## 1. 运行环境（硬约束）

| 项 | 值 |
|---|---|
| 系统 | YodaOS-Sprite，基于 **Android 12（API 31）/ Android Go** |
| 应用 minSdk | **31**（与官方 Sample 一致） |
| Sample targetSdk | 36 |
| 屏幕 | **480 × 640 px，单绿色显示** |
| 调试 | 专用**开发线** + 手机 Rokid AI App 内打开眼镜 ADB |

三条最容易翻车的点：

1. **线材**：零售包装里的是充电线，只能充电。必须用开发线，否则 Android Studio / `adb devices`
   永远看不到设备。这是官方明确点名的头号失败原因。
2. **ADB 开关在手机 App 里**，不在眼镜设置里：手机 Rokid AI App → 眼镜 ADB。
   一次性操作，之后 `adb install` / `logcat` 都直接可用。
3. **Android Go 约束**：内存、后台进程、存储都按 Go 版收紧。大模型/大索引要一次性读入并复用，
   别在每帧里分配大对象。

## 2. 显示规范（决定 UI 怎么写）

- 黑 = **不发光**（等效透明）：背景只能是 `#FF000000`，否则整块屏发绿光、耗电、刺眼。
- 只用绿色（如 `#00FF00`）+ **线条描边**：不要 Material 实心色块、不要大面积填充。
- 安全区：上 80 px、下 80 px 不建议绘制，内容放在 **480 × 480（y=80~560）**。
- **屏上没有触控焦点**：不要用列表滚动、滑动手势、可点击按钮作为唯一入口。
  一屏一内容，多信息用**分页（单击翻页）**，底部固定按键提示条。

本工程沿用官方 `BareScreenLayout / BareKeyLegendBar / BareContentPanel` 这套线框组件，
`GlassesDisplayFrame` 把内容强制钉在 480×640（`density = 1f`），在其它设备上居中显示。

## 3. 输入事件（全部实测自官方专章）

**TouchPad —— KeyEvent**

| 手势 | 事件 |
|---|---|
| 单指单击 | `KEYCODE_ENTER`（`onKeyUp`，`repeatCount == 0`） |
| 单指双击 / 返回 | `KEYCODE_BACK` |
| 单指长按 | `KEYCODE_PROG_BLUE`（同时有广播 `ACTION_AI_START`） |
| 双指单击 | `KEYCODE_NOTIFICATION`（keyCode 83） |
| 双指长按 | `KEYCODE_SETTINGS`（同时有广播 `ACTION_SETTINGS_KEY`） |
| 单指前滑 | `KEYCODE_DPAD_RIGHT` → `KEYCODE_DPAD_DOWN`，≤500 ms 的按键序列 |
| 单指后滑 | `KEYCODE_DPAD_LEFT` → `KEYCODE_DPAD_UP`，≤500 ms 的按键序列 |

**镜腿功能键 —— 有序广播**（须动态注册，`priority = SYSTEM_HIGH_PRIORITY`）

| 事件 | Action |
|---|---|
| 单击 | `com.android.action.ACTION_SPRITE_BUTTON_CLICK` |
| 按下 / 抬起 | `…ACTION_SPRITE_BUTTON_DOWN` / `…_UP`（触发长按则不发送抬起） |
| 双击 | `…ACTION_SPRITE_BUTTON_DOUBLE_CLICK` |
| 长按 | `…ACTION_SPRITE_BUTTON_LONG_PRESS`（默认进关机流程，**可 abort 拦截**） |
| 超长按 | `…ACTION_SPRITE_BUTTON_VERY_VERY_LONG_PRESS` |
| 双指双击/前滑/后滑 | `…ACTION_TWO_FINGER_DOUBLE_TAP` / `_SWIPE_FORWARD` / `_SWIPE_BACK` |

**佩戴与折叠**

- `com.rokid.sprite.ACTION_TAKE_STATUS_CHANGED`，extra `glasses_take_state`："1" 佩戴 / "0" 摘下
- `com.rokid.sprite.ACTION_LEG_STATUS_CHANGED`，extra `glasses_leg_state`："1" 展开 / "0" 折叠

坑：

- 广播**只发给已动态注册**的接收器，静态注册收不到。
- 有序广播要在 `onReceive` 内、`goAsync()` 之前调用 `abortBroadcast()`，否则会连带触发
  系统默认行为（AI 启动、设置、关机）。
- `KEYCODE_ENTER` 必须在 `onKeyDown` 里先 `return true` 吃掉，再在 `onKeyUp` 派发，
  否则会漏给焦点导航，出现"按一次跳两下"。
- 双指单击**不走广播**，只以 KeyEvent 形式上报。
- 指环中间键长按是 `KEY_POWER`（亮灭屏），应用层拦不住。

## 4. 相机（拍题链路的关键）

- 用 **CameraX**（`androidx.camera`），标准 camera2 封装；眼镜只有**后置/朝外**相机。
- 官方 Sample **只绑定业务 UseCase，不绑 `Preview`**：单色屏做取景意义不大，还费电。
- 本工程用 **`ImageAnalysis`** 持续取帧（实时模式）：`STRATEGY_KEEP_ONLY_LATEST` + 1024×768
  + `OUTPUT_IMAGE_FORMAT_YUV_420_888`，Y 平面直接进 ML Kit。
- 若要改成「按一次拍一张」，把 UseCase 换成 `ImageCapture`
  （`CAPTURE_MODE_MAXIMIZE_QUALITY` + `setJpegQuality(100)`）即可，`OcrEngine` 接口不用动。
- **必须异步绑定**：`ProcessCameraProvider.getInstance(ctx)` 用 `addListener`，
  千万别在主线程 `future.get()`，否则进页面直接 ANR（官方 Sample 的 `rememberCameraBound` 已处理）。
- 帧的方向：官方「相机预览描边」示例里真机实测旋转 **270°**；用
  `ImageAnalysis` 时按 `resolution 640×480` 起，输出 480×640。
- 内存：`ImageProxy` 用完**必须 `close()`**，否则缓冲区耗尽，下一次拍照会一直阻塞。

镜腿单击/长按可能触发**系统拍照/录像**；应用内拍照是独立流程，两者可并存（必要时 abort 广播）。

## 5. 其它能力（本工程暂未用，留着扩展）

- 原始音频：`AudioRecord` + `AudioFormat` channelMask **0x6000FC**（8 通道），16000 Hz、
  PCM 16bit；ch0/1 算法后音频，ch2–5 四路麦克风原始数据，ch6/7 硬件回声。
- IMU：`SensorManager` 六轴（陀螺 + 加速度），坐标系同竖屏手机（+X 右、+Y 上、+Z 指向佩戴者）。
- 自启动（来自 Glass3 企业版文档，Sprite 上需真机验证）：
  反射 `android.os.SystemProperties` 写 `persist.vendor.boot.pkg = <包名>`，
  系统重启后拉起该应用；初始化建议延迟 1~2 s。

## 6. 官方 Sample 结构（本工程已裁剪）

```
app/src/main/java/…/
  camera/CameraBind.kt            # 异步 CameraX 绑定（本工程保留）
  input/BareGlassesInputDispatcher.kt  # KeyEvent + 广播统一分发（保留）
  ui/design/                      # 480×640 线框 UI 体系（保留）
  utils/BareMediaStorage.kt       # 落盘目录选择（保留）
  activities/{audio,imu,video,keys,photo}/, sensor/   # 示例页（已删除）
```

删除示例页的原因：它们各自带 ViewModel 与路由，会把"一拍一答"的主线淹没；需要时从
`GlassesBareDevSample.zip` 原包里拷回即可。

## 7. 联调 SOP

1. 开发线插电脑 → 手机 App 打开 ADB → `adb devices` 确认设备
2. `scrcpy` 同屏（480×640），确认界面与按键反馈
3. `adb logcat -v time --pid $(adb shell pidof -s com.openqsy.glasses)` 只看应用日志
4. 装机验证顺序：权限弹窗是否被自动接受（眼镜 HUD 不显示权限对话框）→ 相机就绪 →
   单击能否出答案 → 长按调试页耗时是否符合预算
5. 改题库不必重装：`adb push qbank.idx /sdcard/Download/` 后重启应用
