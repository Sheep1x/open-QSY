# 技术方案：单机拍题答题（Rokid Glasses 裸机）

## 1. 目标 / 非目标

**目标**：眼镜戴上就开始**持续实时扫描**，题目一进视野就出答案，用户不需要按键。
全链路**不连手机、不联网**。

**做法**：`ImageAnalysis` 持续取帧 → 变化检测决定识别频率（静止 1.4 s/次、变化 350 ms/次）
→ 防抖投票（同题 2/5 次命中才锁定）→ 屏上大字号出答案。

**非目标**：彩色题图显示（屏是单绿）、云端大模型兜底（无网）、逐帧全量识别（小电池必炸）。

## 2. 硬约束

| 约束 | 影响 |
|---|---|
| 480×640 单绿，黑=不发光 | 只能线框 + 文字；答案要大字、少字数、分页 |
| Android 12 / API 31，Android Go | 内存紧、后台易被杀；索引必须一次性读入并复用 |
| 无网络 | OCR 与匹配都必须本地；模型/索引随 APK 走 |
| 按键只有 TouchPad + 镜腿 | 交互=单击/双击/长按，无滚动、无按钮 |
| 小电池 + 无风扇 | 连续 OCR 必然发热，必须靠「变化检测 + 节流 + 锁定」把频次压下来 |

## 3. 架构

```
        TouchPad 单击 (KEYCODE_ENTER) / 镜腿单击广播
                          │
                  BareGlassesInputDispatcher
                          │  BareKeyEvent.Click
                          ▼
                     SolveViewModel  ── 状态机 ──►  QuizScreen (480×640 线框 UI)
                          │
         ┌────────────────┼─────────────────┐
         ▼                ▼                 ▼
  ImageAnalysis      OcrEngine          QBankStore
  (CameraX 实时帧,  (ML Kit 中文,      (qbank.idx 倒排,
   KEEP_ONLY_LATEST) bundled 离线)       bigram + idf)
         │                │                 │
         └─ ImageProxy ───┴─ text ──────────┴─ top-3 候选
                  ▲
         变化检测/节流/防抖投票（LiveFrameAnalyzer + SolveViewModel）
```

三个关键分界：

1. **`OcrEngine` 是接口**（入参 `ImageProxy`，出参 `OcrOutcome(text, elapsedMs, error)`），
   换引擎不动上层。ML Kit 只是默认实现。
2. **`QBankStore` 无第三方依赖**：直接读 `assets/qbank.idx`，不碰 SQLite/JNI，
   6622 题 0.91 MB，查询 1~3 ms（PC 侧）。
3. **`SolveViewModel` 独占状态机**：`LoadingIndex → Ready → Busy(拍摄/识别/匹配) →
   Result(candidateIndex) / Failure`。UI 是纯函数，不持有相机与索引。

## 4. OCR 选型

| 方案 | 离线 | APK 增量 | 中文准确率 | 眼镜端速度（估） | 无 GMS 可用 | 结论 |
|---|---|---|---|---|---|---|
| **ML Kit 中文（bundled）** | ✅ 模型进 APK | +25~35 MB | 中~良（印刷体够用） | 300~800 ms | 大概率可用（不走 Play 服务），需真机验证 | **首选**，集成最快 |
| PP-OCRv4 mobile（ONNX Runtime） | ✅ | +15~20 MB（det+rec+dict） | 良~优 | 600~1500 ms | ✅ 完全自包含 | **备选**，ML Kit 起不来就换 |
| Tesseract4Android（chi_sim） | ✅ | +20 MB | 差~中（低分辨率下差） | 1.5~4 s | ✅ | 不推荐 |
| 云端 OCR | ❌ | 0 | 优 | 取决于网络 | — | 与「不联网」冲突，排除 |

决策：**先上 ML Kit**，真机若报 `MlKitException: Failed to initialize detector`（个别
AOSP/Go 固件缺 native 依赖）或准确率不达标，换 PP-OCR —— 只新增一个 `PaddleOcrEngine`，
其余代码零改动。

OCR 前后处理约定：

- 取帧：`ImageAnalysis` + `STRATEGY_KEEP_ONLY_LATEST` + 1024×768，YUV_420_888 直接进 ML Kit；
- 直接 `InputImage.fromMediaImage(image.image, image.imageInfo.rotationDegrees)`，
  省掉一次解码到 Bitmap 的拷贝（Go 设备上这步很值钱）；
- 识别完**立刻 `image.close()`**，否则 `ImageProxy` 缓冲耗尽 → 相机停流（表现：画面定格、之后再也不出结果）；
- `LiveFrameAnalyzer` 用 CAS 串行 + 5 s 看门狗兜底，OCR 万一挂死也不会把相机拖死；
- 识别文本原样交给归一化，不在这里做纠错（纠错交给 bigram 匹配天然容忍）。

## 5. 匹配

见 `03-题库索引格式.md`。要点：题干 bigram 倒排 + IDF 加权覆盖率 + 题干包含度重排
（alpha=0.6），6622 题整卡入镜实测 top1 **98.0%**、top3 **100%**。

匹配层还负责**低置信提示**：`score < 0.62` 时标题改成「答案（匹配度低）」，
并在副标题显示「候选 x/3」，提示用户双击翻候选。

## 6. 性能预算（单次拍题的端到端目标 ≤ 1.2 s）

| 阶段 | 预算 | 依据 |
|---|---|---|
| 按拍到首帧可用 | 150~300 ms | CameraX 已预绑定，`MAXIMIZE_QUALITY` 可能更久 |
| OCR | 300~800 ms | ML Kit 中文，1024×768 单帧 |
| 归一化 + 检索 | 5~15 ms | 6622 题，PC 1 ms 的 5~10× |
| 渲染出答案 | ≤ 32 ms（2 帧） | 480×640 Compose |
| **合计** | **0.5~1.2 s** | 真机核对项 |

调试页（长按）直接显示实测 OCR ms / 匹配 ms，便于现场评估，不用连 logcat。

## 7. 功耗与发热

- **不绑 Preview**：预览在单绿屏上无用，且是主要耗电项。
- **变化检测**：每帧只采样 Y 平面 6×8 个点（极便宜），画面没动就降到 1.4 s/次。
- **防抖锁定**：同题连续命中才锁定，锁定后走慢速档，进一步省电。
- `FLAG_KEEP_SCREEN_ON` 保持常亮，避免用户反复抬头唤醒。
- 调参口：`SolveViewModel.MIN_INTERVAL_CHANGED / MIN_INTERVAL_STILL / SIGNATURE_DIFF / MIN_SCORE`。
- 若实测待机掉电快，把 `KEEP_SCREEN_ON` 改为「识别时开、30 s 后关」。
- 索引一次性 `readBytes()` 常驻（0.91 MB），不做逐条 IO。

## 8. 失败与降级

| 情况 | 处理 |
|---|---|
| `assets/qbank.idx` 缺失/损坏 | 状态页明确报错，不闪退；`Failure("题库加载失败…")` |
| 外置题库解析失败 | 静默回退 assets（日志 warning） |
| 相机未就绪 | 单击提示「相机未就绪，请稍后重试」；不排队 |
| OCR 无文字 | 「没识别到文字，靠近一点再试」+ OCR 耗时留在调试页 |
| 题库无命中 | 「题库里没有这道题（识别 N 字）」 |
| 低置信 | 正常出答案，但标注「匹配度低」+ 提示双击换候选 |
| 权限 | 眼镜 HUD 不弹权限对话框，运行时请求视作已授予；代码仍保留标准请求路径以便手机/模拟器调试 |

## 10. 待决策（需你拍板）

1. **题库规模上限**：现在 6622 题 0.91 MB；若将来 10 万题，索引约 10~14 MB，
   `readBytes()` 仍可接受（~0.3 s），但要改为 mmap 或按科目分片。
2. **答案展示粒度**：只显示「B.稠度」还是附带解析？单屏 480×480，加解析需分页。
3. **多选题**：题库里有多选题，当前直接显示 `answerText`（如「ABC」）。是否需要逐项标答案？
4. **是否要开机自启**（`persist.vendor.boot.pkg`）：属系统属性，需真机验证是否被固件允许。
5. **学术合规**：本工程用于个人学习/技术研究；若对外分发，需自行评估使用场景与当地规则。
